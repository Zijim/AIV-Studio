# 本机调研与工作流接入建议

调研日期：2026-10-11。基于本机实际文件、运行中的 ComfyUI、节点源代码和本次执行记录。

## 结论

现有环境可以支撑首版的文生图、图片编辑、图片放大和图生视频入口。五个小规模任务均实际完成，得到四张正式 PNG 和一个带音轨的 MP4；可读取的临时预览图也已复制到本项目。另验证了一个排队任务的定向取消。

建议把选定工作流准备成版本固定的 API 模板，并为每个模板配置明确的工具参数映射。应用后台直接调用本机 ComfyUI HTTP/WebSocket 接口。接入阶段检查并转换工作流；日常创作只填写允许调整的参数，不让语言模型生成节点或连线。

这次是环境和调用链验证，不是正式产品实现或效果评测。Qwen 高质量分支、正常时长/分辨率的视频、批量候选、运行中取消与重启恢复仍需后续验证。

## 3. 各工作流的接入细节

### 3.1 基础文生图：优先作为快速默认入口

不改变模型和连线即可运行。建议日常开放提示词、输出尺寸、候选数量、种子；采样步数和 CFG 作为预设或高级设置。

UI slot / API 节点映射：

- `3.text`：正向描述。
- `4.text`：负向描述。当前 CFG 0.8；不能默认认为任意负向描述都会有预期效果。
- `5.width` / `5.height` / `5.batch_size`：输出尺寸、批量。
- `1.seed` / `1.steps` / `1.cfg`：随机条件、步数、CFG。
- `12.filename_prefix`：后台生成任务专属输出前缀，不交给助手自由指定文件路径。

保留当前模型、编码器、VAE、采样器和 scheduler。其他尺寸与批量尚未实测。

### 3.2 Qwen 文生图：现有快/质量开关可用

原文件的两个 CLIPTextEncode 提示词 widget 存成了嵌套列表。当前 comfy-cli 转换后会生成 `{"__value__": ["..."]}`，但节点要求字符串，原文件预检报 shape_mismatch。

处理方式：只在项目副本通过 `set_workflow_slot` 把 `4.text`、`5.text` 写成字符串，预检随后通过并真实运行成功。未改用户原文件、模型或节点。

- `4.text` / `5.text`：正、负向描述。
- `6.width` / `6.height` / `6.batch_size`：尺寸、批量。
- `11.value`：已有快速模式开关；true 走 Lightning + `9.value=4` 步 + `12.value=1` CFG；false 走基础模型 + `8.value=50` 步 + `10.value=4` CFG。
- `18.seed`：种子。`18.steps`、`18.cfg` 已被开关节点连接覆盖，不能只修改 sampler 的同名 widget 就以为实际生效。
- `21.filename_prefix`：输出前缀。

建议开放“快速/质量”预设，保持对应模型、LoRA、步数和 CFG 的配套关系。质量分支尚未试跑。

### 3.3 图片编辑：区分单图快速版与多图质量版

`图片编辑.json` 实际只使用 `7` 的单张图片。`8`、`9` 是 bypass 模式，没有提供第二、第三张参考图；原提示词提及“图2”不代表图2实际输入了模型。

单图快速版映射：

- `7.image`：通过 ComfyUI 上传接口得到的图片引用。
- `3.prompt` / `4.prompt`：编辑指令、负向描述。
- `13.width` / `13.height`：明确控制输出尺寸。`18` 缩放、`19` 取尺寸节点没有连接到最终输出链，修改其参数不会影响生成尺寸。
- `1.seed`：种子；保留现有 Lightning 4 步、CFG 1。
- `16.filename_prefix`：输出前缀。

`图片编辑qwen.json` 的第一、第二张图已启用，第三张 bypass；快速采样/解码/保存分支是 muted 模式，当前只执行 40 步、CFG 4 的质量分支。这里 `13.width/height` 连接到 `19`，实际尺寸由第一张图经 `18` 缩放后的尺寸决定。

建议首版先接入已实测单图快速版；多图参考、质量版作为另外准备好的工具变体。在接入阶段明确分支与输入要求，避免每次对话临时启停节点。不能从“可选参考图”标题推断所有情形都能自动省略第二张输入。

### 3.4 SeedVR2 放大：按目标尺寸调用

已有 3B FP8、CPU offload、block swap 与 VAE 分块设置，本次原样保留。

- `1.image`：输入图。
- `5.resolution`：目标短边，**不是倍率**。
- `5.max_resolution`：任意边的最大限制；达到限制时按比例缩小，会影响实际倍率。
- `5.seed`：种子。
- `6.filename_prefix`：输出前缀。

“放大两倍”需要根据真实输入宽高计算目标短边和长边上限，再检查结果尺寸。实测正方形 1024→2048 成功；非正方形、透明图和更高分辨率尚未验证。工作流已有 alpha 恢复路径，但本次输入是 RGB，不能据此宣称透明图已验证。

### 3.5 MiniMax H3 图生视频：子工作流可以接入

它使用本地模型和本地节点，本次预检没有 partner API 节点、不消耗 Comfy 云端生成积分。模型文件名 MiniMax 不等于外部付费调用。

UI slot：

- `114.image`：输入第一帧。
- `115.aspect_ratio` / `115.megapixels`：实际输出尺寸来自 ResolutionSelector；`105.width`、`105.height` 被连接覆盖。
- `105.prompt`：镜头、运动、音频要求。
- `105.value_1`：希望的秒数。
- `105.noise_seed`：种子。
- `105/9.steps`：子工作流内部步数。
- `92.filename_prefix`：输出前缀。

comfy-cli 能展开子工作流；展开后条件节点为 `105:104`、采样调度为 `105:9`、种子为 `105:15`，仍保留原连线。不能把这些 ID 当作任意新版本工作流的永久接口，必须绑定模板版本与校验值。

帧数计算：`max(5, round(seconds × 24))` 向上对齐到 `17k+5`。因此 1 秒→39 帧→1.625 秒；5 秒→124 帧→约 5.167 秒。应在执行方案里显示对齐后的帧数与时长。

`119`、`120` 的图片缩放/取尺寸没有接到输出链。源代码显示 first_frame 会直接伸缩到指定画布，而非自动保留输入比例；默认横屏配竖图可能拉伸。建议默认跟随输入比例，改变比例时明确展示处理方式。

该版本 SaveVideo 的 history 把 MP4 放在 `outputs["92"]["images"]` 列表里。因此不能仅凭字段名 `images` 判为图片，要根据文件格式/媒体探测确定类型。本次已用 PyAV 检查视频帧数、尺寸、时长和音轨。

`MiniMax_H3.json` 无图片输入，可用于文字生成视频；`MiniMax_H3_Ref2VA.json` 使用另一模型做参考素材生成。首版以实测 `video_minimax_h3_i2v.json` 为主，其余能力尚未验证。

## 4. 推荐的应用调用方式

### 接入阶段

1. 用户原工作流只读，复制到应用自己的工具模板区。
2. 读取 `/object_info`，用实际节点 schema 检查类型、可用模型和输入。
3. 展开子工作流、处理已确认的保存格式兼容问题，生成固定 API 模板。
4. 校验连接覆盖、启停分支、必需素材和所有输出节点，执行小规模试跑。
5. 保存工作流版本/hash、参数白名单、输入/输出角色、限制与实测状态。

### 日常执行

1. 助手输出结构化工具方案，例如 `tool_id + input_asset_ids + parameters`，工作台展示并允许调整。
2. 后台校验项目归属、素材存在、参数范围与资源限制；确定具体 seed、真实尺寸和帧数。
3. 图片通过 `POST /upload/image` multipart 上传，指定专属子目录且 `overwrite=false`。本次上传返回 `AIV_probe_20261011/t2i_zimage_00001_.png` 引用，随后编辑、放大、视频都成功使用。
4. 把白名单参数写入固定 API 模板，持久保存**实际将提交的请求**，调用 `POST /prompt` 获得 `prompt_id`。本次 MCP 的 run_workflow 完成了这一环节。
5. 使用 `/ws?clientId=...` 获取 executing、progress、executed、execution_success/error/interrupted；重连后读取 `/queue`、`/history/{prompt_id}` 核实状态。逐步百分比应按当前节点展示，不能假装是整项任务完成比例。
6. 根据产物引用调用 `GET /view?filename=...&subfolder=...&type=output|temp`，复制到项目素材区，保存文件校验、来源任务、输入资产和参数。
7. 输出类型以文件和媒体探测为准；有明确输出节点角色时区分最终图、中间图与临时预览。temp 表示存储位置，不等于创作中的中间步骤。当前四条图片链的 temp 图都是末端预览，不能冒称得到额外中间图。
8. 复制与记录提交完成后，应用才显示“完成”；生成成功但复制失败保留“已生成、尚未保存”，稍后补存，不重新生成。
9. 取消按具体 prompt_id 定向操作。该版本优先使用 `/api/jobs/{job_id}/cancel`，其运行状态检查和中断具有原子性。旧版本的队列删除/interrupt 兼容策略需单独验证，不能假定携带 ID 的旧 interrupt 与新接口同样安全。避免全局清空队列或无目标 interrupt。

应用保有自己的任务表、素材表、项目引用和恢复日志。ComfyUI history 是执行状态来源之一，不是长期素材数据库。调研中 comfy-cli 的本地 jobs 列表出现旧的 queued 记录，但服务器实时 `/queue` 为空，说明不能只依据 CLI 本地状态判断当前任务。

本次已使用 MCP 快速验证调用；长期产品建议直接访问 ComfyUI API，便于精确处理实时事件、恢复和文件复制。MCP/CLI 仍可作为接入调试手段，不必成为应用唯一运行依赖。

## 5. 保护与未验证项

本次未安装/更新节点或模型，未重启 ComfyUI，未修改原工作流或配置，未移动/删除已有产物。测试工作流、记录和项目副本位于 `D:\Project\AIV_Agent2\comfy_probe`；ComfyUI 输出和上传分别位于自己的 `output\AIV_probe_20261011`、`input\AIV_probe_20261011`，原件保留。释放缓存通过 ComfyUI 自己的接口完成。

后续优先验证：正常尺寸单图编辑、Qwen 质量分支、多图输入、正常时长视频、批量候选、运行中取消及已有产物保留、临时产物实时收集、服务/应用重启恢复、磁盘不足补存。语言模型服务尚未选择或连接；这些实测只覆盖创作执行层。

收尾核验：13 份原工作流文件的 SHA-256 均与本次记录一致；服务器运行队列和等待队列均为空。测试完成后已再次请求 ComfyUI 释放模型缓存，服务器继续保持运行。

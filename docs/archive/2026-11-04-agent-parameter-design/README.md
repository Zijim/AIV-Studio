## 如何理解这份规格

规格基于当时由后端代码组织固定阶段、模型在路由和专用规划节点作判断的对话系统。原文使用的 agent 称呼沿用当时讨论，不代表该规格已经定义了由模型根据工具结果自主推进的执行过程。

这是旧架构下的未实现提案，不是新版 agent 的开发指令、当前待实施计划或功能完成说明。原文中的“必须”“首批”“调用预算”等属于当时提案的上下文。

后续可参考的内容包括：

- 稳定工具配置与明确的开放参数范围。
- 工具默认值、单次任务配置与历史执行证据隔离。
- 按任务来源继承，区分生成素材的配置与本次素材用途。
- 参数意图、自动策略和最终执行数值的区分。
- 基于目标和反馈调整相关参数、保留无关设置的共享原则。
- 参数权限、确定性校验、模板副本、执行与素材追溯。

路由／编写的固定阶段、模型调用次数、何时读取工具资料、工具选择后能否重选以及流程继续条件，应结合新版架构重新设计，不能直接从旧规格机械搬用。原来对慢速创作和额外 GPU 试生成的顾虑仍作为产品背景保留；具体过程约定由新版任务确定。

后续开发宜从归档复制出新的适配规格，再明确哪些设计继续采用、哪些替换；归档保持当时版本，避免新旧设计互相覆盖。最近一次评审的七项问题尚未逐项讨论完成，不应视为已采纳的解决方案。
